# 7. Устройство библиотеки

## Главная идея

tvision-rs общается с экраном только через трейт `platform::Backend`:

```rust
pub trait Backend {
    fn size(&self) -> Point;                                    // размер в символах
    fn read(&mut self, timeout: Duration) -> Option<RawEvent>;  // клавиша, мышь, размер
    fn flush(&mut self, screen: &ScreenBuffer, cursor: Option<Point>, insert: bool);
    fn suspend(&mut self) {}
    fn resume(&mut self) {}
    fn system_clipboard(&self) -> bool { false }
}
```

У tvision-rs уже есть реализации для терминала Unix, консоли Windows и
«невидимый» `HeadlessBackend` для тестов. tvision-gui добавляет ещё одну —
`GuiBackend`, — и больше ничего в tvision-rs не меняет. Поэтому все
представления, диалоги, редактор и справка работают в окне без изменений.

## Два потока

Turbo Vision устроен на **блокирующих** циклах: `Program::run()` в цикле
вызывает `backend.read()`, а модальный диалог (`exec_view`) запускает
вложенный такой же цикл. Окно ОС, наоборот, устроено на **обратных вызовах**:
цикл событий winit сам вызывает обработчик для каждого события и должен
крутиться постоянно, иначе окно «зависает». В macOS этот цикл обязан работать
в главном потоке.

Чтобы не переписывать Turbo Vision на обратные вызовы, они работают в разных
потоках:

```
 главный поток: окно (winit)                поток программы: Turbo Vision
 ───────────────────────────                ─────────────────────────────
 App (ApplicationHandler)                   Program::run()
   клавиатура → keys::translate ─┐            │
   мышь → ячейка                 ├─ канал ──▶  GuiBackend::read()  (recv_timeout)
   размер окна → сетка           ┘  RawEvent   │
                                               │  обработка, отрисовка
   Renderer.update ◀─ Shared::frame ◀────────  GuiBackend::flush()
   softbuffer.present   + EventLoopProxy        (кадр + «проснись»)
```

* **События окна → программе**: канал `std::sync::mpsc` с «сырыми» событиями
  `RawEvent` (клавиша, состояние мыши, новый размер). `read(timeout)` — это
  `recv_timeout`, поэтому таймауты Turbo Vision (автоповтор мыши, часы в
  tvdemo) работают как в терминале.
* **Кадры программы → окну**: последний кадр кладётся в общую ячейку
  `Shared::frame` (`Mutex<Option<Frame>>`), а окно будится сообщением
  `UserEvent::Frame` через `EventLoopProxy`. Если программа нарисовала
  несколько кадров, пока окно было занято, окно возьмёт только последний.
* **Служебные сообщения окну** (`UserEvent`): `Exit`, `Title`, `Visible`,
  `Grid` — их посылают `Drop` бэкенда, `set_title`, `suspend/resume`,
  `set_screen_size`.

## Жизненный цикл

### Запуск через `run`

1. `run` создаёт цикл событий в главном потоке и «заготовку» подключения
   (`Connection`: концы каналов, `EventLoopProxy`, общая ячейка кадра).
2. Запускается поток `tvision-app` с `app_main`; запускается цикл событий.
3. Цикл событий вызывает `resumed`: окно создаётся **скрытым**, загружается
   шрифт, создаётся поверхность softbuffer. Окно сообщает размер сетки
   через одноразовый канал `ready`.
4. В потоке программы `GuiBackend::new()` забирает заготовку подключения
   и ждёт `ready` — после этого `Program::new` знает размер экрана.
5. Первый `flush` → `UserEvent::Frame` → окно показывается и рисует кадр.
6. Работа: события идут в одну сторону, кадры — в другую.
7. `app_main` завершается → `GuiBackend` уничтожается (`Drop` посылает
   `Exit`), а страж в потоке ещё раз посылает `Exit` (на случай паники).
8. Цикл событий завершается, `run` дожидается потока и возвращает результат
   `app_main` (или пробрасывает её панику).

### Без `run` (Windows, Linux)

`GuiBackend::new()` не находит заготовки и сам запускает поток
`tvision-window`, в котором создаёт цикл событий с флагом «можно не в главном
потоке» (`with_any_thread`). Дальше — как выше, с шага 3. Когда программа
завершается, `main` возвращается и процесс завершается вместе с окном.

### Закрытие окна пользователем

`CloseRequested` → в канал отправляется Alt+X. Если программа вышла — шаги 7–8.
Повторный `CloseRequested` → `std::process::exit(0)`. Если окно исчезло, а
программа продолжает читать события, `read` получает «канал закрыт» и
возвращает Alt+X; после ~50 таких чтений процесс завершается.

## Модули

| Файл | Что внутри |
|------|-----------|
| `src/lib.rs` | реэкспорт tvision, документация крейта |
| `src/backend.rs` | `GuiBackend` (трейт `Backend`), `run`, `set_title`, `set_screen_size`, `ProgramExt`, общие данные `Shared` |
| `src/app_window.rs` | `App` — обработчик цикла событий winit: создание окна, клавиатура, мышь, изменение размера, мигание курсора, горячие клавиши окна, вывод кадра |
| `src/keys.rs` | перевод клавиатурных событий winit в `KeyEvent` Turbo Vision |
| `src/render.rs` | `Renderer`: ячейки → пиксели, перерисовка изменений, курсор, картинки CP437 для управляющих символов |
| `src/font.rs` | `FontSet`: поиск системных шрифтов, ленивые запасные шрифты, метрики ячейки, растеризация (fontdue) |
| `src/boxdraw.rs` | программная отрисовка рамок и блоков |
| `src/config.rs` | `GuiConfig`, `VGA_PALETTE`, переменные окружения |

## Внешние зависимости

| Крейт | Зачем | Что даёт |
|-------|-------|----------|
| `winit` 0.30 | окно и события | Win32, Cocoa, X11, Wayland; клавиатура, мышь, HiDPI, полный экран |
| `softbuffer` 0.4 | вывод кадра | копирование массива пикселей в окно без GPU и OpenGL |
| `fontdue` 0.9 | шрифты | растеризация TrueType/OpenType на чистом Rust |

Ни одна из них не требует системных библиотек для сборки на Windows и macOS.
Про Linux — в [разделе 8](08-platforms.md#linux-и-bsd).

## Тесты

`cargo test` в tvision-gui проверяет то, что не требует окна:

* таблицу символов рамок и их геометрию (линии доходят до краёв ячейки,
  соседние символы стыкуются, форма двойных углов);
* блоки и плотность теней;
* смешивание цветов, рисование фона, восстановление ячейки под курсором;
* отображение управляющих символов.

Логику самих программ удобнее проверять на `HeadlessBackend` — см.
[раздел 2](02-porting.md#тесты).
